# 04. Мастер настройки и первый вход

После установки веб-сервиса при `setup_completed=false` NovaTIP перенаправляет на `/setup/`.

## 1. Открыть мастер

1. В браузере откройте `https://novatip.example.local/setup/` (или IP ВМ).
2. Если видите предупреждение о самоподписанном сертификате — для стенда можно продолжить (в бою используйте доверенный сертификат).

## 2. Шаги мастера (1–9)

| № | Шаг | Что сделать |
|---|---|---|
| 1 | Лицензия | Загрузить `.novalic` или включить **dev grace 14 дней** |
| 2 | Организация | Имя организации + **префикс локальных ID** (не `CVE`/`BDU`) |
| 3 | Оформление | Логотип, заголовок и текст страницы входа |
| 4 | База данных | Подключиться **или** создать УЗ+БД (см. ниже) |
| 5 | Администратор | Логин/ФИО/email/пароль **веб-пользователя** NovaTIP |
| 6 | Источники | NVD API key, KEV, БДУ |
| 7 | Почта | SMTP (можно заполнить позже в Настройках) |
| 8 | Telegram | Токен/chat или «Пропустить» |
| 9 | Финиш | Завершение → страница входа |

## 3. Шаг «База данных» — два режима

УЗ PostgreSQL ≠ администратор веб-интерфейса.

### 3.1. Режим A — Подключиться к существующей БД

Используйте, если УЗ и БД уже созданы по [02_STACK_INSTALL.md](02_STACK_INSTALL.md) или Docker init.

1. Выберите **Подключиться**.
2. Заполните: Host (`127.0.0.1`), Port (`5432`), имя БД, пользователь, пароль, SSL mode.
3. Нажмите **Проверить подключение**.
4. При успехе — **Сохранить и продолжить**.
5. Мастер запишет `DATABASE_URL` в `.env`.

Типичные ошибки:

| Сообщение | Что проверить |
|---|---|
| connection refused | `systemctl status postgresql` |
| password authentication failed | пароль УЗ / `pg_hba.conf` |
| database does not exist | создайте БД или режим B |
| permission denied | GRANT на схему `public` |

### 3.2. Режим B — Создать УЗ и базу

1. Выберите **Создать УЗ и БД**.
2. Введите данные **суперпользователя** PostgreSQL (`postgres` + пароль) — **одноразово, не сохраняется**.
3. Укажите имя новой БД и новой УЗ (например оба `novatip`) и пароль УЗ.
4. Нажмите **Создать УЗ и выдать права**.
5. Мастер выполнит CREATE USER/DATABASE/GRANT, проверит вход под новой УЗ и сохранит `DATABASE_URL`.

В Docker Compose роль/БД уже созданы init-скриптом — достаточно режима A.

## 4. Первый вход

1. После шага 9 откроется `/accounts/login/`.
2. Слева — брендинг и CSS-анимация; справа — форма.
3. Войдите логином администратора из шага 5.
4. Саморегистрации нет — пользователей создаёт администратор.

## 5. После входа

1. Проверьте **Дашборд**.
2. Откройте **Настройки** → вкладки (Организация, Оформление, Источники/Sync, Почта, Telegram, БД).
3. Sync запускается из вкладки **Источники / Sync**, не из главного меню.
4. Меню: Дашборд · Уязвимости · Заявки · Настройки. Wiki нет.
